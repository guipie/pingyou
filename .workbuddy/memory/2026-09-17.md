## 聊天窗口三项优化：删除不刷新 / 供应商级发图 / 屏友会话设置入口

### 1. 右键删除会话后左栏不消失（刷新才没）—— 真正的根因
- 症状：`chatStore.delConversation()` 把库里记录删了（刷新即消失），但左栏列表不动。
- 根因**不在 store 代码**（`conversations.value = filter(...)` 本身正确），而在
  **`@tauri-store/pinia` 的跨窗口同步**：
  - `DEFAULT_SYNC = true`，插件用 `watch(store.$state, patchBackend, { deep: true })`
    把**整个 store 状态**推给 Rust 后端；收到 `tauri-store://state-change` 广播时
    `store.$patch(payload.state)` 回灌本地 —— **整状态「最后写入者获胜」**。
  - 致命细节：`BaseStore.processChangeQueue()` 在 `patchSelf()` **之前 `unwatch()`、之后才 `watch()`**，
    所以被别的窗口用旧列表覆盖后，本地**不会**把正确状态重新推回去 → 回滚「粘住」。
  - 5 个窗口（main/preference/winchat/winmsg/provider-add，tauri.conf.json 里声明 = 启动即创建）
    各有一份 chat store，互相覆盖，于是出现「删了还在、刷新（重新读库）才对」。
- 修法：
  - `stores/aichat.ts` 的 `defineStore` 加第三个参数
    `{ tauri: { filterKeys: ["conversations"], filterKeysStrategy: "omit" } }`，
    把**数据库承载的列表**排除出 save/sync；`activeChatId` / `currentConversation` 仍同步，
    悬浮输入窗照旧知道在跟谁说话。每个窗口本来就会在 `App.vue` 里跑 `initStore()` 自行读库。
  - 配套（必须）：排除同步后，别的窗口可能「内存里没有这个会话」，原来补的是
    `chatStore.addConversation(id)` —— 那是 `INSERT OR REPLACE`，会**用默认标题/默认模型把已有会话原地覆盖**。
    → 新增 `ConversationRepo.getConversationById()`（**必须解密 apiKey + 还原 JSON 字段**，
    否则 provider 会变成字符串）与 `chatStore.loadConversation(id)`；
    `ensureModelConversation()` / `sendWinMessage()` 都改成「先查库、再考虑新建」。

### 2. 供应商级发图 + 识图后转文本模型
- 判定口径改变：`canSendImage` 由「当前选中模型是 vision」改为「**该供应商下有 vision 模型**」
  （`hasVisionModel` = `providerVisionModel` 是否存在，取 `models.find(type === "vision")`）。
- 三条链路（`useTauriAIChat.sendMessage`）：
  1. 当前模型是视觉 → 原样发图（不变）。
  2. **只发图**、当前模型不是视觉 → 自动换成那个视觉模型**直接作答**（`requestModel = 视觉模型`）。
  3. **图片+文字**、当前模型不是视觉 → **两段式**：先用视觉模型识图拿到描述，
     再把「描述+文字」交给**文本模型**（`allowVision = false`，由 `imageDescription` 顶替图片）。
- 关键实现点：`buildUserContent()` 增加 `imageDescription` 分支 —— 没图或不让发图时，
  用描述文本拼成 `【用户上传了一张图片，其内容描述如下】\n<desc>\n\n<user text>`。
  历史轮次同样走这条兜底，所以多轮上下文里的图片信息不会丢。
- 新增 `describeImage()`：复用同一条 `tauriFetchChat`，只换模型、清空历史、只带这张图，结果不流式展示。
- 新增模块级 `stage`（`describing` / `answering`），UI 把「思考中」换成「正在识别图片」。
- 中间描述**以可折叠提示展示**（用户选择）：`chat-msg.vue` 在回答气泡内用原生 `<details>/<summary>`，
  带 `visionModel` 小标签；落库时把 `imageDescription` / `visionModel` 打包进 `options` 列
  （表里没有独立列，`chat-msg-repository.ts` 加了 `packMessageOptions` / `mapMessageRow`）。
- 顺手修文案：`modelImageUnsupported` 原文案让人「切换到视觉模型」，现已改为
  「该供应商下没有可用的视觉模型，无法识别图片。」

### 3. 屏友卡片的设置图标（原 `<i class="i-solar:settings-broken" />` 是死的）
- `usePingyouChat.ts` 新增 `openChatSettings(model)`：`ensureModelConversation` → `setCurrentConversation`
  → `showWindow(PREFERENCE)` → `routeStore.goCurPage(ContainerRouters.chatModelSetting)`。
  **必须先设 currentConversation**，否则 `chat-settings.vue` 的 `onMounted` 会把用户弹回首页。

  `saveConversation`）；未配置时**只弹提示、不跳转**（用户选择）。
- `pingyou/index.vue`：两处卡片的 settings 图标补上 hover 绿色 + `title` + `@click.stop`。

## internal_toggle_maximize 报错排查（chat 麦克风按钮）
- 现象：点击聊天工具栏麦克风按钮时控制台报 window.internal_toggle_maximize explicitly denied。
- 根因：Tauri 注入的 drag.js 在 data-tauri-drag-region 上双击时调用 internal_toggle_maximize（双击最大化），而 capabilities/default.json 自 first commit 起显式 deny 该权限。项目里 drag region 很多（preference 侧栏/logo/聊天内容容器 index.vue:228、winchat 卡片），双击极易误触。
- 修复：deny 改为 core:window:allow-internal-toggle-maximize，恢复标准双击最大化行为并消除报错；cargo check 通过。需重编译重启应用生效。
- 麦克风语音逻辑（SpeechRecognition）本身与该报错无关，不受影响。


## 语音识别 not-allowed 修复（WebView2 麦克风权限）
- 现象：点麦克风按钮 toast "not-allowed"（SpeechRecognition onerror）。
- 根因：wry 0.55.1 的 PermissionRequested 处理器只放行剪贴板，麦克风权限走 WebView2 默认行为=静默拒绝。
- 修复：新增 src-tauri/src/utils/webview_mic.rs，经 with_webview 给每个 webview 追加 WebView2 PermissionRequested 处理器，仅放行 MICROPHONE（其余权限维持默认拒绝）；lib.rs setup 里对 app.webview_windows() 逐个挂载；Cargo.toml 增加 [target.'cfg(windows)'] webview2-com = "0.38.2"（与 wry 对齐）。cargo check 通过，需重编译重启。
- 若仍失败需检查 Windows 系统级"麦克风-桌面应用"隐私开关。
