## 修复依赖大版本升级导致的构建 / 启动失败

背景：用户成批升级了 Rust 依赖（zip 2→8、aes-gcm 0.10→0.11、base64 0.22→0.23、rand 0.8→0.10、
cpal 0.15→0.18、webview2-com 0.38.2→0.39.1、tauri-plugin-pinia 3→5、tauri-plugin-prevent-default 1→5），
`cargo clean`（清掉 40.9GiB）后 `pnpm run tauri dev` 在 tauri-build 的 ACL 阶段失败：
`Permission prevent-default:default not found`。

改动：
1. `src-tauri/capabilities/default.json`：删除 `"prevent-default:default"`（v5 无此权限）。
2. `src-tauri/Cargo.toml`：`webview2-com` 由 0.39.1 回退到 **0.38.2**（对齐 wry 0.55.1，否则类型不匹配）。
3. `src-tauri/src/ollama/gateway.rs`：`rand::distributions::Alphanumeric` → `rand::distr::Alphanumeric`；
   `use rand::Rng` → `use rand::RngExt`；`rand::thread_rng()` → `rand::rng()`。
4. `src-tauri/src/utils/crypto.rs`：去掉 `aes_gcm::aead::OsRng` 与 `aead::rand_core`;
   改用 `rand::rng().fill_bytes()`；`Key/Nonce` 改用 `From<[u8;N]>` 构造，去掉废弃的 `from_slice`。
5. `src-tauri/src/voice/mod.rs`：`config.sample_rate().0` → `config.sample_rate()`；
   `&config.config()` → `config.config()`（cpal 0.18 按值收 StreamConfig）。

验证：`cargo check` 通过（**0 error / 0 warning**，29.01s）；`vite build` 通过（17.80s）。

未决（已在回复里抛给用户）：Rust `tauri-plugin-pinia` 5.0.2 与 npm `@tauri-store/pinia` 3.7.1 错配。
已核实命令层兼容（JS 命令集是 Rust 子集）、`filterKeys` 在 JS 侧故上次的同步修复仍有效；
完全对齐需 `pinia ^3 → ^4`，属前端较大改动，等用户决定。

## 把 rdev / gilrs 从 git 依赖改成项目内置（vendor）

需求：用户担心上游仓库被删，要求不再从 GitHub 拉这两个依赖。

做法：
1. 源码取自 cargo 缓存 `~/.cargo/git/checkouts/{rdev-*,gilrs-*}/<short-sha>/`，
   用 `tar --exclude-vcs ...` 拷进 `src-tauri/vendor/rdev/`、`src-tauri/vendor/gilrs/`（117 个文件，约 1.5MB）。
   注意 gilrs 仓是 workspace，`gilrs/` 与 `gilrs-core/` 两级要一起拷（`gilrs` 用 `path = "../gilrs-core"`）。
2. 根 `Cargo.toml` 的 `[workspace]` 加 `exclude = ["src-tauri/vendor", "src-tauri/vendor/*", "src-tauri/vendor/**"]`。
   **必须 exclude**：否则 path 依赖会自动成为 workspace 成员，其 dev-deps（eframe/egui/winit…）会被解析进 Cargo.lock。
3. `src-tauri/Cargo.toml` 改成 `rdev = { path = "vendor/rdev" }`、
   `gilrs = { path = "vendor/gilrs/gilrs", default-features = false, features = ["xinput"] }`。
4. vendored 清单的两处改动（其余保持上游原样，并在文件里写 `NOTE(vendored)` 注释）：
   - 删掉 `[dev-dependencies]`（rdev 的 serial_test/tokio、gilrs 的 eframe/egui_plot/env_logger、
     gilrs-core 的 env_logger）。实测 lock 里 eframe/egui/winit/serial_test/console_log… 全部消失。
   - 加 `[lints.rust]` 把上游自带的 16 条告警压掉（rdev: `unreachable_patterns`、`static_mut_refs`；
     gilrs: `mismatched_lifetime_syntaxes`）。

关键坑（重要）：
- **cargo 只对「非 path」来源的依赖加 `--cap-lints allow`**。同一个包从 git 依赖换成 path 依赖后，
  上游原本被静默的告警会全部冒出来（实测 rdev 15 条、gilrs 1 条）。
- **path 依赖在 Cargo.lock 里会列出该包「声明的全部依赖」，包含未启用的 optional**。
  所以 gilrs-core 的 lock 条目会多出 `windows`、`serde`（git 依赖时不会有）。这是正常的、惰性的，
  不影响编译：`cargo check -v` 里 gilrs-core 的 rustc 参数只有 `feature="xinput" / "rusty-xinput" / "winapi"`。
  （试过把 `default = []` 想清掉这些边 —— 无效，已还原成上游的 `default = ["wgi"]`。）
- gilrs 的 `build.rs` 会在编译期读 `gilrs/SDL_GameControllerDB/gamecontrollerdb.txt`（536KB，原本是 git submodule），
  **必须一起拷**，否则报 "Did you forget to pull the SDL_GameControllerDB submodule?"；
  它会按目标平台过滤后写到 `OUT_DIR/gamecontrollerdb.txt`（Windows 出 810 行）。
- `gilrs-core/src/platform/mod.rs` 里 `xinput` 与 `wgi` 是 **互斥** 的（同时开会 compile_error），
  所以 `features = ["xinput"]` 不能动。

验证：`cargo check` 通过（0 error / 0 warning）；build.rs 产物正常生成；lock 中 rdev/gilrs/gilrs-core 已无 source 行。
剩下唯一 git 依赖是 workspace 根 `Cargo.toml` 里的 `tauri-nspanel`（仅 macOS 用），已告知用户可后续同样处理。
